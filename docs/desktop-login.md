# 闲鱼授权失效与自动续期

适用范围：闲鱼工作台桌面版1.0.3起；1.0.5目前为Mac验证版，尚未发布。本文说明软件实际处理方式，不承诺闲鱼平台永久授权。

## 工作台登录和闲鱼授权有什么不同？

| 状态 | 用途 | 失效后的处理 |
| --- | --- | --- |
| 工作台登录 | 访问本机管理页面、消息和设置 | 重新登录工作台；记住密码可帮助填写，但不是闲鱼授权 |
| 闲鱼平台授权 | 从闲鱼获取消息、商品、订单并执行允许的操作 | 先尝试使用有效长期凭证恢复，平台要求验证时重新扫码 |

1.0.3让桌面访问Cookie和工作台登录token随本次应用运行有效，修复旧版本连续运行24小时后可能出现的403。主动退出登录或重启仍会撤销旧工作台会话。源码/Docker网页部署仍保留原24小时登录期限。

## 如何完成一次可续期的闲鱼授权？

1. 1.0.5打开工作台的扫码登录，会启动独立的闲鱼官网窗口。扫描工作台或该官网窗口显示的二维码。
2. 在手机上确认登录，并完成官网要求的验证。请保留官网窗口，等待工作台完成授权。
3. 软件会在头像弹窗开启真正的“保存登录信息”开关，核对长期凭证和同账号真实IM令牌后保存。成功后关闭此次独立窗口；若平台不提供长期凭证，会明确提示。
4. 检查账号状态与消息连接。扫码完成、拿到Cookie和消息已连接是不同步骤，不能仅凭“Cookie刷新成功”判断恢复。

## 自动续期会做什么？

软件每20分钟进行授权检查，Session过期时按平台长期或备份凭证尝试静默登录，并遵守平台冷却时间。候选授权必须通过真实IM令牌和同账号核验，才会条件保存、用于重连。后台旧响应不能覆盖刚刚重新扫码得到的新授权。

## 为什么升级后还需要重扫？

如果旧授权已经过期，而且没有平台签发的有效长期凭证，修复代码无法凭空恢复登录。这种情况下需重新扫码一次。网络失败、冷却和不明确响应不会直接等同于永久失效；平台要求手机验证时仍需人工完成。

1.0.3/1.0.4的直接二维码接口可能登录成功但仍无权开启长期保存。Mac实测这种凭证的官网设置返回`canOpenLongLogin=false`，完整网页登录后才变为可开启。因此只升级后台续期逻辑，或在另一个普通浏览器打开开关，都不能补齐工作台缺少的长期凭证；1.0.5修正了桌面扫码入口。网页/Docker部署仍使用原接口流程。

## 网页上的“保存登录信息”开关会同步到工作台吗？

普通浏览器和工作台使用各自的登录存储。在浏览器开启该开关，不代表工作台数据库已经拿到同一套新凭证。应在工作台完成自己的扫码和验证流程，不要在Issue或聊天中粘贴Cookie尝试同步。

## 可以保证一直不扫码吗？

不能。长期凭证是否下发、何时撤销和是否要求验证由闲鱼平台决定。2026-09-08 Mac实测完整官网登录后取得约30天凭证，保存状态重启浏览器及后台免扫码续期通过。这只是该次平台签发期限；真实账号跨24小时续期仍需实际观察。

## 排查聊天加载失败时看什么？

先确认工作台能否正常登录，再检查对应闲鱼账号是否显示需重新扫码。403本身不足以判断是哪一层失效；如果账号授权正常而单条会话仍失败，记录发生时间和脱敏错误到[Issues](https://github.com/genoooool/xianyu-super-butler/issues)。不要反复重发买家消息来测试连接。
